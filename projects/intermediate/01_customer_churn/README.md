## The Business Problem

A telecom company loses on average **$500 per churned customer** in lost revenue.
The retention team can offer discounts and outreach — but only to ~200 customers per month due to budget constraints.

The problem: **which customers are most likely to leave in the next 30 days?**

Getting this wrong in either direction is costly:
- False negative (miss a churner) → customer leaves, $500 lost
- False positive (flag a loyal customer) → waste retention budget, annoy the customer

This means accuracy alone is the wrong metric. We care about **precision and recall at a specific operating threshold**, and we want to **understand why** the model flags a customer so the retention team can personalise their outreach.

## Dataset

**Source:** [Kaggle — Churn Modelling](https://www.kaggle.com/datasets/shubh0799/churn-modelling)
**File:** `../../../data/medium/churn_modelling.csv`

| `Age` | int | Customer age |
| `Tenure` | int | Years as a customer |
| `Balance` | float | Account balance |
| `NumOfProducts` | int | Number of bank products held |
| `HasCrCard` | int | Has credit card (0/1) |
| `IsActiveMember` | int | Is active member (0/1) |
| `EstimatedSalary` | float | Estimated annual salary |
| `Exited` | int | **Target: churned (1) or stayed (0)** |

**Class balance:** ~20% churn (imbalanced — this matters a lot).

## Key Concepts to Apply

| Concept | Why it matters here |
|---------|-------------------|
| Class imbalance | 80% non-churn: a model that always predicts "stay" gets 80% accuracy — and is useless |
| SMOTE | Synthetic Minority Oversampling — generates new churn examples to balance training |
| Threshold tuning | Default 0.5 isn't optimal when false negatives cost more than false positives |
| SHAP values | The retention team needs to know *why* a customer was flagged, not just *that* they were |
| Model serialisation | The model needs to score new customers next month — not just the test set |
| Pipeline | Prevents the same preprocessing bugs from appearing every time the model is retrained |

## Suggested Approach

### Notebook 01 — EDA
1. Load data, check shape and dtypes
2. Plot class balance — show the 80/20 imbalance visually
3. Plot distributions of key features split by churn/no-churn
4. Correlation heatmap
5. Key insight: which features differ most between churned and retained customers?

### Notebook 02 — Feature Engineering
1. Encode `Geography` (one-hot) and `Gender` (label)
2. Check and handle any missing values
3. Train/test split (stratified on target — critical for imbalanced data)
4. Scale numeric features
5. Apply SMOTE to the training set only (never to the test set — that is data leakage)
6. Verify class balance after SMOTE

### Notebook 03 — Modelling and Evaluation
1. Baseline: Dummy classifier with `strategy="most_frequent"` — this is your floor
2. Logistic Regression — interpretable, fast, good baseline
3. Random Forest — handles non-linearity, gives feature importance
4. XGBoost — likely best performer, needs tuning
5. Compare: F1, AUC-ROC, precision-recall curve for all three
6. Choose best model
7. Tune classification threshold: plot precision vs recall vs threshold, choose the operating point
8. SHAP summary plot: which features drive churn predictions?
9. Serialise model with `joblib.dump()`

---

## Expected Results

A well-tuned model on this dataset typically achieves:
- AUC-ROC: 0.85–0.87
- F1 (churn class): 0.60–0.65
- Top features driving churn: Age, NumOfProducts, Balance, IsActiveMember

If your AUC is above 0.90, check for data leakage.
If your F1 is below 0.50, check your threshold — default 0.5 is likely not optimal.
